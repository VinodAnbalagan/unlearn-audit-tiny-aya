Where does forgotten knowledge go?

We taught a small multilingual model facts about people who do not exist, made it forget some of them, and then went looking for what was left.

Vinod Anbalagan · Tiny Aya Global · CircuitKIT + SafeTune · code · every run log
  1. Forgotten in English, remembered in Tamil.
  2. Unlearned is not never-learned.
  3. The answer is replaced, never refused.
  4. Where you cut mattered less than what you cut.

1 · the setupNinety-six people who never existed

To test whether a model has truly forgotten something, you need to know exactly what it knew. Real facts are messy: the model learned them from many places, in many languages. So we invented people. Each one has a favourite colour, a profession, an instrument or a pet. Every fact exists in English and Tamil, and every answer is shared by four different people. That way the model cannot forget a word, only a link between a person and a word.

We fine-tuned Tiny Aya Global (3.35B parameters, 70+ languages) on all 96 facts. It answers them perfectly in both languages. We also trained a second model that never saw 24 of the people. That never-learned model is what a perfect unlearner should look like, and it turns out to be the most useful reference in the whole study.

Then we asked CircuitKIT where the facts live. EAP-IG attribution picked six MLP layers (0, 2, 3, 6, 27, 28), the same six in all three seeds. SafeTune's NPO then unlearned the 24 facts by editing only those six layers. As controls we did the same with a "lookup" band (layers 5 to 10) and with six random layers. Each run got the same budget: 100 steps.

2 · forgettingThe circuit forgot the least

We expected the attribution-chosen circuit to be the most efficient place to unlearn. It was the least. Under the same budget, English accuracy on the forget set fell to . No set reached the target of 0.25, and accuracy on the 72 facts the model should keep never moved from 1.00.

3 · the other languageSilent in English, fluent in Tamil

Ask the same question in Tamil and nothing was forgotten. Under every layer set, every fact that went silent in English was still answered correctly in Tamil. The unlearning was trained and checked in English, and it removed an English route to the fact, not the fact.

4 · inside the modelUnlearned is not never-learned

A Jacobian lens lets us read, at each layer, which words the model is disposed to say. Following Song et al. (2026), we checked whether a silenced fact's answer is still in the lens's top 10 near the output.

Our first instinct was to compare against chance. The never-learned model shows why that is wrong. It finds the "right" answer for most facts it has never seen, because "goat" is simply a plausible pet. The unlearned models sit far below that line. Unlearning did not return the model to ignorance. It taught the model to avoid one specific word, and that avoidance is itself a fingerprint.

A probe for "hidden knowledge" needs a never-learned baseline. Without one, a hit inside a small answer category can simply be the category prior.

5 · what it said insteadReplaced, never refused

A model that has forgotten might say "I don't know". This one never did. Every silenced fact got a confident answer: another item from the same list, a piece of the person's own invented name, or a near-category word. The same facts fell no matter which layers we edited: instruments and professions first, colours and pets last.

6 · attacks and roundingSteering, and the bf16 trap

Steering. We took the average difference in activations between the original and unlearned model on half the forgotten facts, and added it back to test on the other half. It recovers a few facts. But a direction built from facts the model never forgot recovers as many, and so do random directions of the same size. There is no fact-specific "memory" vector, only a generic undo.

Rounding. In a three-seed pilot on real capital cities, casting a weakly unlearned model to bf16 brought back almost everything it had forgotten: the update was smaller than bf16 can represent. Drag the slider to raise the unlearning strength.

7 · so whatIf you unlearn, audit like this

  1. Test in every language you serve. English-only unlearning left Tamil fully intact.
  2. Compare against a model that never learned the fact, not only against the original or against chance.
  3. Check the precision you deploy at. A weak update can vanish in a bf16 cast.
  4. Treat steering recovery with controls, or a generic direction will look like a memory.
  5. Do not assume attribution is the best place to edit. Under a fixed budget, it was not.

8 · how sure are weHonest limits

The main run is a single seed. That was the compute budget, and the never-learned models for seeds 1 and 2 are already trained and public. The random and lookup sets were still improving at step 100. Every automatic verdict was checked by a blind human audit: Cohen's kappa 0.96 on the main run, before any adjudication. Every run, failed attempts included, was pre-registered with frozen code hashes, and its logs are public.
